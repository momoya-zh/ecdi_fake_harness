# MCP 通知流实现要点

三种传输（stdio / Streamable HTTP / legacy SSE）统一走 hub 分发。核心是 **单一分发口径**，而不是 `scanSSE` 各写各的。

## 1. 传输层行为

- Streamable HTTP：GET 通知流，405 = 不支持即停
- 断流带 Last-Event-ID 退避重连
  - 重连 5 次耗尽才判死（legacy SSE 同口径）
- stdio：通知与响应同走一条 stdout，按 id 分流

## 2. 示例配置

```json
{
  "servers": {
    "docs": {
      "transport": "http",
      "url": "http://127.0.0.1:9120/mcp",
      "timeout": 60
    }
  }
}
```

### 验收清单

1. tools/list_changed 触发重拉工具表，新工具免重启可调
2. 断流自愈期间调用方拿到显式错误，不静默挂起
3. 死亡通知在坏传输上不丢（death-race 牙齿对覆盖）

> 设计取舍：通知流只做「送达 + 分发」，语义消费（如 progress 的 GUI 进度面）另批——
> 避免一个 Phase 夹带两件事。

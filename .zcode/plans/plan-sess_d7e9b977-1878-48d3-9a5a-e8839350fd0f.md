# 提案卡 + diff 预览（ask 门升级）

## Context

`run_command`/`write_file`/`edit_file` 已上线，但 ask 门的问句是纯文本截断：`edit_file` 新旧串各截 60 字符、`run_command` 截 160 字符——**用户审不了他在允许什么**。这是"日常可用"最大的洞（提示注入的最后防线就是这道门）。本批把 ask 从"文本问句"升级为"结构化提案卡"：write/edit 显示**真 unified diff**，run_command 显示完整命令+作用域，task 委派显示任务+预算。

关键探查结论（设计依据）：
- 协议 §9:684 允许同主版本内加可选字段（旧 GUI 按 I5 忽略）；§3.3 有 v5 可选字段的成文措辞先例。`ask` 现形状 = `t/seq/ts/id/kind/question/options/default`（PROTOCOL.md:217），无字段表。
- **调用顺序完美适配**：`runToolCall` 先 emit 带**完整 args** 的 `block_start`（session.go:726-727），再过 ask 门（:733），`executeTool` 在批准**之后**（:743）。diff 需要的"当前磁盘内容"只有 core 知道 → **diff 由 core 算**（GUI 无 diff 库，且 2MB 内容不该进 GUI）。
- GUI ask 卡已有折叠体先例（CollapsiblePanel，AppTranscript.cpp:755-774）；按钮在头部行（探针契约 AppInternal.h:263-265）；`MarkAnswered`/`ApplyAnsweredLook` 是首次回答与 rebuild 的同构单点（:905-987）。**既有路径字节不变**是硬纪律：无 detail 的 ask（全部现有夹具 77 行）渲染必须与今天逐位一致。

## 方案

### 1. 协议（只增不改，不新 kind、不加新不变量）

- **PROTOCOL.md §3.6**：按 §3.3 措辞先例加"★ v5 可选 `detail` 字段"块——`detail` 为对象、必带非空 `tool`；写明"未知 `tool` 或字段缺失 ⇒ GUI 回落问句文本"（renderer 数据，同 `args` 地位，validate 不查——在文档写明这个决定而不是发明没人需要的机器检查）。
- **detail 形状**（扁平、`tool` 判别）：
  - `write_file`: `{tool, path, diff}`（新文件时 `diff` 全 `+` 行）
  - `edit_file`: `{tool, path, diff, replaceAll}`
  - `run_command`: `{tool, command, cwd, timeoutSeconds, note}`（note = 密钥已剔除说明）
  - `task`: `{tool, task, tools, maxTurns, timeoutSeconds}`（对齐 delegationAskPrompt 已有信息）
- **§9 v5 行**补注 `detail`；§7 补一句 diff 配色规格（`+`=ok 色、`-`=err 色、`@@`/头行=muted、上下文=正文）。
- **新夹具** `protocol/fixtures/proposal/write-edit-run-asks.jsonl`（protocol 5，caps [tools,ask,workspace]）：三段 ask 各带 detail，严格 `ask → state=waiting → state=running` 配对、seq 连续。validate.py glob 自动纳入（14→15 份）。
- **不加 I14**：detail 损坏的最坏后果 = 回落问句文本（已有路径），不造恒难触发的机器检查。

### 2. core（diff 计算单点）

- **`core/cmd/ecdi-core/diff.go` [NEW]**：`unifiedDiff(old, new, maxLines int) string`——公共前/后缀行修剪后做行级 LCS（中段超 ~1500 行/侧则窗口截断并标注），context 3 行，`--- / +++ / @@` 头，超 `maxLines`（400）截断加"…（截断，共 N 行）"。
- **`askDetail(name string, args map[string]any, cwd string) map[string]any`**（tools.go，与 askPrompt 同排）：
  - write_file：`os.ReadFile` 当前内容（**只读、批准前**，不存在=新文件），与 `args.content` 算 diff；无变化 → diff 为空串。
  - edit_file：`unifiedDiff(old_string, new_string)`（替换片段即审阅单元；整文件上下文已在 tool_call 卡的 args 里）。
  - run_command / task：填结构化字段，不算 diff。
- **session.go**：`askQuestion` 增 `detail map[string]any` 参数，emit 时并入（:685-692 处）；`runToolCall`（:733）与 `prepareDelegation`（agent.go:127）各传入。**问句文本不动**（askPrompt 原样，E2E 既有断言不破）。
- **测试**：`diff_test.go` [NEW]（新文件/替换/无变化/截断/大文件五案）；`session_test.go` 加 `TestLoopE2E_AskDetailWriteAndEdit`（照 `TestLoopE2E_WriteToolAskAllowLandsOnDisk`:531 模板：waitFor ask → 断言 `detail.diff` 含预期行 → answer allow → 落盘）。

### 3. GUI（渲染 + 探针）

- **App.h**：`TimelineEntry` 增 `detail`（小结构体：hasDetail/tool/path/command/cwd/timeoutSeconds/replaceAll/diff），`CreateAskRow` 解析 `msg["detail"]`（防御：非对象/无 tool → 忽略，走旧路径）。rebuild 同构：MaterializeOne 用同一 BuildAskRow。
- **AppTranscript.cpp BuildAskRow**：有 detail ⇒ **默认展开**的折叠体（决策时刻必须看得见 diff），逐行渲染：`UiKit::Label(mono)` 一行一 Label，`+`→kOkDark、`-`→kErrorDark、`@@`/`---`/`+++`→kDarkMuted、上下文→kDarkInk；行宽裁剪不折行（保对齐，ECDI 逐控件 PushClip 天然裁）。无 detail ⇒ 与今天逐位一致（AskNeedsFold 旧逻辑原样）。
- **新探针 `--proposal-probe`**（ProbeProposal.cpp [NEW]，照 ProbeAgents.cpp 骨架）：读数 `askRows/detailRows/diffRows/plusRows/minusRows/matched`——模型侧（timeline 的 detail）与屏侧（fold body 实际行数）双读数互证；**负对照另跑一支**：demo 夹具（无 detail）必须 `diffRows==0`（回落路径完好）。判据写 regress.py（`check_agent_probe_negative` 同款 B 类）。
- **接线**：ProbeState.h / ProbeTypes.h / CliOptions.h（flag + AnyProbeLike）/ main.cpp（arg + help）/ AppStream.cpp 探针表（:362 同形条目）/ AppSummary.cpp。
- **tools/regress.py**：`--proposal-probe`（正向夹具）+ 负对照 + 判据。

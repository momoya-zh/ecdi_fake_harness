V3-GUI done: protocol v3 now has a GUI side, and three defects in the first cut were FOUND BY MEASUREMENT and fixed before landing. What v3 added on the wire: `Prompt` carries a `client_id`, `ProtocolWriter::Workspace(request_id, path)` exists, `Hello` sends protocol 3, `Block` gained `clientId` (parsed at `Transcript.cpp:41`), and `kKnown[]` gained "workspace" -- without that last one every ack increments `unknownTypes` and rewrites every baseline. What v3 added on screen: a prompt is drawn IMMEDIATELY as a transient bubble (`PendingPrompt{clientId,text,status,failure}` + `PendingPromptView{clientId,row}`), and the core echo with the same id REMOVES that bubble and creates the canonical row in its place, so confirming never inserts a second block (`canonicalMatches=1`). The workspace lease is shown as the path the CORE resolved, not the path the GUI picked: `workspacePath` is written only from an `ok:true` ack's `path`, so the sidebar cannot claim a directory the core never adopted -- at startup the GUI asks once (cwd) and waits, which is why live messages went 431 -> 432 and that is an ACCOUNTED change, not noise. THE THREE DEFECTS: (1) the hello gate rejected any core whose caps lacked "workspace" (`if (!protocolIsV3 || !capsValid || !m_sess->workspaceCap) { ... Exit(); }`), which nullified both hostile fixtures -- seq-gap and truncated-final-line are `protocol:3` with caps ["tools","ask"] and ["tools"], so both were refused at line 1 and reported blocks=0 deltas=0 seqGaps=0 violations=0: the negative controls were certifying nothing. PROTOCOL 3.1 says an undeclared core means `GUI must not show the workspace picker`, and 9 only refuses a core whose protocol is ABOVE the ceiling; neither says "must equal 3, must declare workspace".
